# Atlas Query Contract — CHANGELOG

One line per version, semver-justified (spec §2).

- **0.1.0** (Batch AQC-1) — Initial contract: a snapshot of today's actually-consumed wire shapes for the five query families (FocusQuery, TraversalQuery, TextWindowQuery, SceneQuery, ExplorationRoundTrip) plus the new `/api/contract` version-advertisement endpoint. Zero behavior change to any pre-existing endpoint — this version documents what the server already serves and the client already consumes; it does not redesign anything (spec §9 Q4, recommended scope).

- 0.2.0 (DB-4a): re-recorded through the one assembly path (`export_aqc_examples`) — every fixture's "version" is the 32-hex manifest root and every "edge" a canonical edge id (spec §3.6); no scenario text changed (MAJOR class, MINOR bump under the pre-launch 0.x rule). Disclosed: `scene-time.json` also catches up one value that had drifted since the fixture was last exported two roots ago (`galilee-1` quiet place `total_events` 16 -> 17, an event the corpus gained in the meantime) -- not an identity change.

- 0.3.0 (DB-4b): re-recorded through the one assembly path once more -- the version root moved when the logical dump widened to the node projections, the resolved chronology, the heading index, the red-letter spans and the nine folded sidecars (spec 3.4, 5.3-5.6; every section table is now in the root). Only the 19 fixtures' `version` values change; no edge id, no pid, no scenario text (MAJOR class, MINOR bump under the pre-launch 0.x rule).

- 0.8.0 (CONTRACT-1a, 2026-09-27): schema derived from `contracts/openapi.yaml`; shapes carry the domain names (`NodeCard`, `EdgePage`, `Contents`, `TextWindow`, `Contract`); every served type published; `x-queries` retired. A published shape name changed (MAJOR class, MINOR bump under the pre-launch 0.x rule), and the advertised range moves with the document -- `/api/contract` answers 0.8.0/0.8.0 and the client's own `ClientVersion` follows. WITHDRAWN, disclosed: four closed vocabularies are now published as prose only, as `type: string` with the values named in the field's description -- `Scene.mode` (was `time` | `scripture`), `ContentsRoot.kind` (was `book` | `document`), `ContentsRoot.group` (was `OT` | `NT`), `ContentsChild.kind` (was `chapter` | `article`); spec 3 defers those four enums to FOCUS-1 and the map migration. Also withdrawn: the `x-source` provenance annotation on every shape (the Rust that serves it is now the document's source, named in its header line). KEPT: `Contract.min_version`/`max_version` still carry the MAJOR.MINOR.PATCH pattern and `manifest_schema`/`section_schema_version` still carry `minimum: 1`. ALSO ADDITIVE (same batch, the coverage law): `scene-query.feature` and `text-window.feature` each name the URL their query is served at, with an `I query "<url>"` step in the scenario that already pins that query -- three added step lines, no scenario added, removed or reworded, no fixture touched. A route named nowhere but a comment is a route with no promise, and `atlas-contract/tests/contract_coverage.rs` now refuses one. ALSO IN THIS BATCH (the typed-parameter pass): every query parameter is read as its own type, so a word outside a closed query vocabulary is refused instead of falling through to the default -- `bad_scope` is a NEW code in the taxonomy (400), joining `bad_ref`, `bad_window`, `bad_kind`, `bad_dir` and `bad_corpus`, and an unknown `dir` on `/api/text` now answers `bad_dir` where it silently read as `onward`; one scenario is added (`an unknown scope is bad_scope`, with its own fixture `text-window-bad-scope`), none removed or reworded. FOUR FURTHER BEHAVIOUR CHANGES, none of which any scenario, fixture or pact covered before, all disclosed: (a) `/api/place/{id}` reads its period by the same law every other pair of years is read by -- a year that is not a year, one year given without the other, and a span that ends before it starts are each `bad_window`, where the first two were served as 200 with the place's default name and the third silently ignored; (b) a conditional request (`If-None-Match`) whose query cannot be read is refused with that parameter's 400 rather than answered 304, because a route reads its parameters before it answers; (c) `/api/node/{id}/edges` asked with a well-formed id that names no node AND an unknown `kind` answers `bad_kind` where it answered `not_found`, because an unreadable query is refused before the resource is looked up (a MALFORMED id still answers `bad_ref` first, as it always did); and (d) `/api/text` asked with `corpus=concord` and `scope=chapter` answers 400 `bad_scope` where it answered 400 `bad_dir` -- a chapter is a Scripture reading, so the scope is what a Concord caller must change, and the route's published prose now says so and says what a Concord caller asks for instead. Each is pinned by its own test; (a) and (d) also by one new scenario each in BOTH harnesses, with their own fixtures (`place-period-bad-window`, `text-window-concord-chapter-bad-scope`) -- two scenarios added, none removed or reworded, so the corpus is 50 scenarios / 201 steps. ADDITIVE to the document: four closed vocabularies are published as enums -- `EventKind` (`EventDetail.kind`, `VerseEvent.kind`, `Heading.kind`, one `$ref` carrying the description once), `LandmarkKind` and `LandmarkSize` (`Landmark`), and `Confidence` (`ProvenanceEntry.confidence`) -- `WindowDir` and `TextScope` join them as the `dir` and `scope` parameters' own schemas, `corpus` gains a `$ref` to `Corpus`, and `NodeKind`, `EdgeKind` and `PositionKind` each publish a description. WITHDRAWN, disclosed: each route's 400 now lists only the codes its own parameters can produce, so a route that reads nothing but a path segment (`/api/catechism/item/{id}`, `/api/event/{id}`, `/api/narrative/event/{id}`, `/api/contents/{corpus}`) advertises no 400 at all, and the others name their own codes rather than all five. ALSO ADDITIVE to the document, no response byte changed: `ErrorBody` and `ErrorInner` are registered components and every 400/404/500 content is a `$ref` to the first, where the references to them used to resolve to nothing; `ErrorInner.code` is the published `ErrorCode` enum (`bad_ref`, `bad_kind`, `bad_scope`, `bad_window`, `bad_corpus`, `bad_dir`, `not_found`, `internal`) rather than an open string; every object component carries `additionalProperties: false`; the document gains a top-level `tags:` list, one sentence per family; a border point is the published `Point` shape -- an array of two numbers, published without `format: double` -- where `LandMask.rings` and `Polity.rings` used to publish a per-position schema list a generated client refuses; `ScenePlace.brightness` carries `maximum: 255` again; and `info.description` says what `x-atlas-relations` holds. The derived AQC shapes carry no `description` or `summary` at all now: the harnesses read shapes, so prose belongs to `openapi.yaml` alone and editing a sentence no longer moves this version. Response bytes are unchanged, which the pacts, the two harnesses and the byte-identity tests prove.
