# HOTFIX-4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline
> — standing order NO SUBAGENTS forbids subagent-driven-development for this
> batch). Steps use checkbox syntax for tracking.

**Goal:** Fix whole-DAG chronological traversal (every dated event, not just
narrative members), rectify duplicate Gospel-era event identities that make
the global timeline lie about ordering, enforce affordance honesty
(traversable vs not), and make the 20-verse wire cap's truncation honest.

**Architecture:** One additional server-side resolver output (a "timeline"
position alongside "narrative" positions) computed from a single global
chronological index built once in `AtlasData::finish()`, served by the
SAME `/api/narrative/event/{id}` endpoint (wire shape extended to an object).
A curated `EventMerge` table (mirroring `atlas_core::merge`'s same-place
pattern) collapses duplicate Theographic/curated event identities before
that index is built, with a fail-loud ETL validator sweeping for any
unlisted near-duplicate. Client: one new popover section
(`EventTimelineSection`), a wire-carried `kind` on heading/event-membership
rows driving a new quiet CSS class, and a truncation-aware label on the
existing `MiniReaderExpand` control (no parallel components anywhere).

**Tech Stack:** Rust (atlas-core/atlas-etl/atlas-server), Blazor WASM C#
client, Playwright (TypeScript) black-box suite bound to tests/ux/CONTRACT.md.

**Spec:** `.superpowers/sdd/2026-08-17-bible-atlas-m1/batch-hotfix4-brief.md`
plus the coordinator's live amendment (duplicate-identity rectification,
folded into requirement/task numbering below as "Amendment A-D").
