# Atlas Query Contract — CHANGELOG

One line per version, semver-justified (spec §2).

- **0.1.0** (Batch AQC-1) — Initial contract: a snapshot of today's actually-consumed wire shapes for the five query families (FocusQuery, TraversalQuery, TextWindowQuery, SceneQuery, ExplorationRoundTrip) plus the new `/api/contract` version-advertisement endpoint. Zero behavior change to any pre-existing endpoint — this version documents what the server already serves and the client already consumes; it does not redesign anything (spec §9 Q4, recommended scope).

- 0.2.0 (DB-4a): re-recorded through the one assembly path (`export_aqc_examples`) — every fixture's "version" is the 32-hex manifest root and every "edge" a canonical edge id (spec §3.6); no scenario text changed (MAJOR class, MINOR bump under the pre-launch 0.x rule). Disclosed: `scene-time.json` also catches up one value that had drifted since the fixture was last exported two roots ago (`galilee-1` quiet place `total_events` 16 -> 17, an event the corpus gained in the meantime) -- not an identity change.

- 0.3.0 (DB-4b): re-recorded through the one assembly path once more -- the version root moved when the logical dump widened to the node projections, the resolved chronology, the heading index, the red-letter spans and the nine folded sidecars (spec 3.4, 5.3-5.6; every section table is now in the root). Only the 19 fixtures' `version` values change; no edge id, no pid, no scenario text (MAJOR class, MINOR bump under the pre-launch 0.x rule).

- 0.8.0 (CONTRACT-1a, 2026-09-27): schema derived from `contracts/openapi.yaml`; shapes carry the domain names (`NodeCard`, `EdgePage`, `Contents`, `TextWindow`, `Contract`); every served type published; `x-queries` retired. A published shape name changed (MAJOR class, MINOR bump under the pre-launch 0.x rule), and the advertised range moves with the document -- `/api/contract` answers 0.8.0/0.8.0 and the client's own `ClientVersion` follows. WITHDRAWN, disclosed: four closed vocabularies are now published as prose only, as `type: string` with the values named in the field's description -- `Scene.mode` (was `time` | `scripture`), `ContentsRoot.kind` (was `book` | `document`), `ContentsRoot.group` (was `OT` | `NT`), `ContentsChild.kind` (was `chapter` | `article`); spec 3 defers those four enums to FOCUS-1 and the map migration. Also withdrawn: the `x-source` provenance annotation on every shape (the Rust that serves it is now the document's source, named in its header line), and `ScenePlace.brightness`'s `maximum: 255`. KEPT: `Contract.min_version`/`max_version` still carry the MAJOR.MINOR.PATCH pattern and `manifest_schema`/`section_schema_version` still carry `minimum: 1`. ALSO ADDITIVE (same batch, the coverage law): `scene-query.feature` and `text-window.feature` each name the URL their query is served at, with an `I query "<url>"` step in the scenario that already pins that query -- three added step lines, no scenario added, removed or reworded, no fixture touched. A route named nowhere but a comment is a route with no promise, and `atlas-contract/tests/contract_coverage.rs` now refuses one. ALSO IN THIS BATCH (the typed-parameter pass): every query parameter is read as its own type, so a word outside a closed query vocabulary is refused instead of falling through to the default -- `bad_scope` is a NEW code in the taxonomy (400), joining `bad_ref`, `bad_window`, `bad_kind`, `bad_dir` and `bad_corpus`, and an unknown `dir` on `/api/text` now answers `bad_dir` where it silently read as `onward`; one scenario is added (`an unknown scope is bad_scope`, with its own fixture `text-window-bad-scope`), none removed or reworded. ADDITIVE to the document: four closed vocabularies are published as enums -- `EventKind` (`EventDetail.kind`, `VerseEvent.kind`, `Heading.kind`, one `$ref` carrying the description once), `LandmarkKind` and `LandmarkSize` (`Landmark`), and `Confidence` (`ProvenanceEntry.confidence`) -- `WindowDir` and `TextScope` join them as the `dir` and `scope` parameters' own schemas, `corpus` gains a `$ref` to `Corpus`, and `NodeKind`, `EdgeKind` and `PositionKind` each publish a description. WITHDRAWN, disclosed: each route's 400 now lists only the codes its own parameters can produce, so a route that reads nothing but a path segment (`/api/catechism/item/{id}`, `/api/event/{id}`, `/api/narrative/event/{id}`, `/api/contents/{corpus}`) advertises no 400 at all, and the others name their own codes rather than all five. Response bytes are unchanged, which the pacts, the two harnesses and the byte-identity tests prove.

- 0.7.0 (D5, 2026-09-19): (a) ADDITIVE -- a Person's `NodeCardOut` carries `person` (`PersonLifeOut`: gender, the source's own `birth_year`/`death_year`, the corpus-mention `first_year`/`last_year` -- never a lifespan -- and the curated `eternal` + Scripture `eternal_grounds`; omitted, never null, on every other kind); three relations appended to the vocabulary (`parent-of`/`child-of`, the symmetric `partner-of`, `participates-in`/`participants`) so a person's kin and events are queried edges through the generic traversal; (b) a blessed fixture moved -- the core section gains the `parent_of`/`partners`/`participates` tables and the Person payload columns, so the core logical hash and the version root moved. MINOR under the 0.x policy. Fixtures re-recorded through the one assembly path.

- 0.6.0 (D3, 2026-09-18): (a) ADDITIVE -- every `/api/text` unit carries `edge_summary` (kind, count: the unit's inhabited frontier, `node_card`'s own projection), so a corpus page can make only units with edges clickable without an N+1 of node-card calls; (b) a blessed fixture moved -- the Book of Concord's document tier is document ⊃ article Container rows (the Bible's own shape; `member-of` at a paragraph names its article, at an article its document), so the concord section and the version root moved. Under the 0.x policy a moved blessed fixture is MINOR; the additive field would have been PATCH alone. Fixtures re-recorded through the one assembly path; no scenario text changes beyond the version numbers.

- 0.5.0 (LEX-1, 2026-09-18): the fifth section. `Section::SHIPPED` gains `lexicon` (13,548 `LexiconEntry` nodes, 431,280 `Occurs` rows), so the manifest has a fifth line and the version root moves ONCE more -- a new-section move the spec foresaw (spec 7, 8 row 7), not a cutover move: the four other sections' logical hashes are byte-identical (pinned in `atlas-graph/tests/lexicon_section_real_data.rs`). Every fixture's `version` is re-recorded through the one assembly path (`export_aqc_examples` builds its graph from raw sources via `GraphService::build`, the four-corpus arm, so its root moved for the registry rows and its verse fixture shows no `words` -- exactly as it shows no `commented-on`/`spoken-by`; the SERVED path answers `words 26` at JHN.3.16, pinned in `atlas-graph/tests/lexicon_section_real_data.rs` and visible through `bibex node`). No scenario text changes beyond the version numbers.

- 0.4.0 (DB-4c, the LAST root move of the cutover): `event_date` gained the chronology's `source_meta` columns (`meta_to_year`, `order_key` -- the curated values the Event wire serves; DB-4b had dropped `order_key` as a duplicate of `seq`, which it is not), so core's logical hash and the root moved once more. Only the 19 fixtures' `version` values change; no edge id, no pid, no scenario text (MAJOR class, MINOR bump under the pre-launch 0.x rule). Also (additive, DB-4c's read cutover): `ContractOut` gains optional `manifest_schema` and `section_schema_version` -- the served identity is the manifest's (spec 9).
